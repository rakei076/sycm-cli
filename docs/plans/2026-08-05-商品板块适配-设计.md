# 商品板块适配 — 设计

日期：2026-08-05 ｜ 状态：设计已确认，待转实现计划

## 1. 背景

sycm-cli 目前对「商品」板块只覆盖三处：`item-list`（商品排行 / 商品360 列表层，共用同一接口）、`cate-list`（品类360）、`new-product-*`（新品追踪三个子接口）。单品 360 的深度页、退款分析、流量来源、视频分析等一律没有。

`fields.json` 字典 62 条全部 `scope` 为 `home-table` / `home-overview`，商品域字段一条没有。

## 2. 侦查结论（2026-08-05 实测）

侦查方法：用已登录浏览器读 `performance.getEntriesByType('resource')` 取请求 URL 与完整参数（**零额外 API 请求**），页面指标选择器（`.low-common-index-picker-control`）读权威中文名，再用 CLI 重放读字段码。21 个接口重放 19 通、2 因缺参失败（均可修）。

关键结论：

1. **单品 360 是 11 个模块，不是 5 个**。早期从 `commDate.json?tab=service,flow,sale,customer,content` 推出的「5 个 tab」是错的，那个参数只表示哪些 tab 需要查可用日期。实际模块：销售分析、流量来源、详情分析、退款分析、价格分析、标题优化、内容分析、客群洞察、关联搭配、服务体验、单品诊断。
2. **接口散在 7 个路径前缀**：`/cc/`、`/flow/`、`/domain/`、`/csp/api/`、`/s_content/`、`/qos/`、**`/mc/`**（2026-08-06 补：客群细分的 `lossrisk.json` 在这族下，首次侦查漏了——因为当时只录到客群洞察的一个子标签）。现有 `param_style` 只有 `sycm-v1` / `cc-v2` 两种，不够用。
3. **`/domain/oneQuery.json` 是通用取数网关**，不是单点接口。已实测 `domainCode`：`tao.shop.qos.item`、`tao.shop.shop.item`、`tao.shop.shop.sku`；形态为 `domainCode` + `showType=overview|trend` + `dateType` + `dateRange` + `indexCodes` + `extMap={JSON}`。
4. **`item-list` 字段薄是 `indexCode` 没传全，不是权限问题**。页面指标选择器有 30 项（同时最多选 5），CLI 目前只拿到 8 个字段。
5. **商品搜索接口** `/cc/common/item/search.json?keyword=` 支持商品标题 / 商品ID / 商品URL / **货号**，返回 `id`、`itemNO`（货号）、`title`、`price`、`stockCnt`、`pictUrl`、`url`，50 条。`itemNO` 可与 shop-ledger 的款号账本对齐。
6. **`menu --all` 另有隐藏路由**：隐藏分组「商品内容」（商品视频 / 推荐微详情视频 / 头图视频 / 购后视频）+ 12 个下钻详情页。含下钻页商品板块约 25 条路由。

完整能力清单见同目录 `2026-08-05-商品板块-全量清单.md`。

## 3. 目标

把商品板块做到与首页数据概览同等成熟度：命令可用、字段入字典、口径有警告、有测试。范围为全量（用户已确认），按阶段交付，每阶段结束都有可用命令。

非目标：不做写操作（本 CLI 全只读）；不做已下线页面（异常预警、销量预测）。

## 4. 架构改动

### 4.1 参数层抽象

现状：`fetch_preset()` 里用 `if style == "cc-v2" / else` 硬分支拼参数，preset 只能声明 `path` / `orderBy` / `indexCode` / `extra_params`。

改为：把「参数拼装」从 `fetch_preset` 里拆成独立的 param builder，按 `param_style` 分派。新增三种：

| style | 适用 | 形态 |
|---|---|---|
| `sycm-v1` | `/csp/api/*` 旧接口 | `startDate`/`endDate`=YYYYMMDD + `dateType=day` + `dateRange=day` + `pageNo` |
| `cc-v2` | `/cc/*` | `dateRange="D\|D"` + `dateType` + `page`/`pageSize` + `indexCode` |
| `flow-v2` | `/flow/*` | 同 cc-v2，另需 `flowBizType` / `activateBoost` / `crowdType` |
| `domain-gw` | `/domain/oneQuery.json` | `domainCode` + `showType` + `indexCodes`(注意是复数) + `extMap`(JSON 字符串) + `bizCode` |
| `csp-item` | `/csp/api/refund/*`、`/csp/api/rfdAnalysis/*` | `itemId` + `refundDateType` + `caseScene` + cc-v2 式日期 |

`/s_content/*`（内容分析）与 `/qos/*`（评价、售后明细）实测参数形态与 `cc-v2` 一致（`dateRange` / `dateType` / `page` / `pageSize` / `order` / `orderBy` / `indexCode`），只是多几个专有参数（`accountRole`、`keyword`、`skuId`、`imprEmotion` 等），复用 `cc-v2` + `extra_params` 即可，**不新增 style**。故 6 个前缀共 5 种 style。

preset 增加可选字段：`item_scoped: true`（该命令必须带 `--item-id`）、`date_type_required: true`（缺 `dateType` 服务端报 22102）。

理由：不加这层，11 个模块每个都要写特例分支，`fetch_preset` 会膨胀成不可维护的巨函数。这是 `sycm_cli.py` 已经 85KB 的现实压力下必须做的隔离。

### 4.2 单品命令的公共前置

单品 360 所有模块都需要先有 `itemId`。命令统一支持两种入参：
- `--item-id <id>` 直接指定
- `--search <款号|标题关键词>` 走 `/cc/common/item/search.json`，命中唯一则自动使用；命中多条则列出候选并停止（**不自动选第一条**——猜错会导致整份分析张冠李戴）

### 4.3 文件拆分

`sycm_cli.py` 已 85KB。本次新增约 20 个命令，继续堆进单文件会失控。拆出 `sycm_item.py` 承载商品板块的 preset 定义与命令实现，主文件只保留注册。字典与护栏仍共用主文件的实现。

## 5. 命令面

### 阶段 1 — 搜索 + 单品360 止血三件套

| 命令 | 接口 | 产出 |
|---|---|---|
| `item-search <kw>` | `/cc/common/item/search.json` | 货号/标题/ID/URL 搜商品 → id、itemNO、title、price、stockCnt |
| `item-360` | `/cc/diagnose/coreIndex.json` + `/cc/live/item/sale/overview.json` | 核心指标：本店值 + 环比（`*Crc`）+ `*Cmpt`/`*CmptCrc` 对比值。**`*Cmpt` 的口径未核实**（2026-08-05 实测其数量级与本店值对不上，全落在 0–1，不是同行绝对值），不得当同行对比解读。销售总览为实时快照，忽略 `--date`（同日实测：13 个不同日期区间返回完全相同数值） |
| `item-sku-list` | `/cc/live/v2/item/sale/sku/list.json` | SKU 维度：加购件数、支付金额/件数/买家数、现有库存、售罄率、库存可售天数 |
| `item-flow-source` | `/flow/item/source/tree/support.json` | 流量来源树（多级 children）：uv/pv/收藏/加购/支付/转化率/客单价 |
| `item-refund` | `/csp/api/refund/item/reason/list/v2.json` + `/cc/refund/item/sku/list.json` + `/cc/refund/item/prop/list.json` | 退款原因分布、哪个 SKU 退得多、哪个属性退得多 |

选这五个的理由：`item-search` 是所有单品命令的入口；其余四个合起来回答「这个款为什么不行、哪个尺码在退、流量从哪来」——大码女装退货率高，这是决策密度最高的一组。

## 6. 字典策略

每封一个命令，把该接口字段回写 `fields.json`：

- 中文名来自页面指标选择器或表头 → `status: verified`，`note` 记验证日期与方法
- 只有字段码、中文名未核 → `status: candidate`，`cn` 暂等于字段码
- 试探失败 → `status: rejected`
- `scope` 填对应命令名

`fields.json` 永不含真实数值、店名、商品 ID。

## 7. 口径警告（写入 `note`，分析时必须遵守）

- 退款类字段沿用现有警告：支付时间口径退款率近 7 天仍在爬升，禁止用近 7 天下结论；签收退款率 T-3 才出值。
- 单品 360 默认 `dateType=today` 是实时口径，盘中会跳。CLI 一律默认 `day`，取稳定汇总。
- `/cc/live/item/sale/trend.json` 单日调用返回 `today`/`yesterday` 两组，不是任意区间序列。
- 商品排行 30 指标服务端同时最多 5 项，分批取回后合并时必须按 `itemId` 对齐，不能按行序。

## 8. 错误处理

- 沿用现有护栏：风控词终止（`RiskTriggered`，退出码 2，绝不重试）、连续 2 次 HTTP 失败终止、夜间 1:00–6:00 禁跑。
- 新增两类已知业务错误的明确提示：`code=1003 input key type not exist`（趋势接口缺 `type`）、`code=22102 时间周期类型不能为空`（`/domain/oneQuery.json` 缺 `dateType`）。命中时提示缺哪个参数，而不是抛原始报文。
- `--search` 命中多条时列候选并以非零码退出，不猜。

## 9. 测试

沿用 `tests/test_sycm_cli.py` 的既有风格（不打网络，构造响应做断言）：

- 每种新 `param_style` 的参数拼装：给定 preset + 日期 + 分页，断言产出的 query 字典完全相等（含 `extMap` 的 JSON 序列化结果）
- `--search` 命中 0 / 1 / 多条三种分支
- `item-list` 分批取 30 指标后按 `itemId` 合并的正确性（含某批缺行的情况）
- 嵌套值提取 `{value, cycleCrc, syncCrc}` 与树形 `children` 的展平
- `fields.json` 断言：商品域字段的 `scope` 必须指向已存在的命令名；`verified` 条目必须有 `note`
