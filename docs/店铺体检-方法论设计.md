# 店铺体检方法论 — 设计文档 (spec)

> 目标:给小卖家一套"能真正帮到用户"的店铺体检方法论。不是命令清单,是"按什么顺序看、说明什么、该动什么"的诊断体系 + 标准化报表体系。面向女装大码类目(高退货、重到款、快上新)。

## 1. 范围

- **做**:①体检流程(6 套诊断动线)②报表体系(5 域)③融合报表(跨 CLI)④互推另外两个 CLI。
- **不做**:①同行对标(小卖家看同行均值是噪音,只和自己过去比)②存报表到文件的功能(存哪儿是用户自己的事,只给方法论)。
- **落地**:体检流程 + 报表体系定义 → `SKILL.md`(机器执行);人看的呈现 → `README.md`(报表形式 + 一句话链接到 SKILL,不复制内容)。

## 2. 底层框架(有出处,不是拍脑袋)

- **主公式**:`支付金额(GMV) = 访客数 × 支付转化率 × 客单价`(要复购 ×复购频次)。任何一天钱变了,先定位是这三个因子哪个动了,再往下钻。
- **先流量、后转化**:流量结构影响转化,不先盘流量会错判。
- **中小卖家聚焦三指标**:支付转化率、客单价、退款率。
- **别被 GMV 骗**:打折冲 GMV 会压平利润;要把订单数/净额/退货率摆在 GMV 旁边。("GMV 繁荣、到账率低"是虚假繁荣。)
- **女装类目加权**:退货率是头号难题(淘宝女装 35–40%,大促更高),"库存是女装头号敌人",退货主因=尺码乱+面料质量。→ 售后/到款权重前置。
- **对比轴**:只和自己过去比 —— 环比(`cycleCrc` 较上一周期)/ 趋势(`home-table` 多日)/ 同比(`syncCrc`/`yearSyncCrc`,可选)。

来源:九数云 GMV 拆解、woshipm 淘宝卖家数据分析、KPITree 电商指标树、新浪财经女装退货率报道。

## 3. 实测校验出的 3 个坑(2026-07-18 逐域实拉验证)

1. **广告复盘用区间、不用单日**:万相台单日成交/ROI 因归因窗口未完成常为 0,复盘查过去 7 天。
2. **客服质检别依赖询单流失/慢响应**:`inquiry-loss-list`/`slow-rsps-list` 常返回 0 条;主力用 `reception-list` + `evaluation-list`(差评) + `fetch-recent`。
3. **同行对标已弃用**:`rivalAvg`/`rivalGood` 有真数据但按决策不采用。

## 4. 报表体系(5 域 = 食材库)

| 域 | 命令 | 回答什么 |
|---|---|---|
| 总览·大盘 | `home-overview` / `home-table`(32项) / `home-trend`(30日) / `grow-factor`;万相台 `charge-summary` / `scene-summary` | 整体好不好、和过去比涨跌 |
| 场·流量与广告 | `grow-factor`;万相台 `scene-daily` / `report-keyword` / `report-campaign` / `report-crowd` / `report-area` / `promo-*` | 钱花哪、哪个渠道/词 ROI 高 |
| 货·商品与款 | `item-list`(排行/360) / `cate-list` / `new-product-*`;万相台 `report-item` / `promo-items` | 哪款爆/烂、测款、新品 |
| 人·客户与客服 | `home-table`(访客/复购字段) / `reception-list` / `evaluation-list` / `fetch-recent` | 复购、客服接待质量 |
| 售后·到款(女装命门) | `home-table` 退款组 / `refund-item-list`(含退款原因) / `sale-item-list` / `evaluation-list`(差评) | 退款率/退货到款/问题款(权重最高) |

## 5. 体检流程(6 套 = 菜谱,调用报表域)

**① 日体检(快检,30 秒扫雷)**
触发:"看看昨天咋样"。动线:`home-table`(和过去比,定量/效率/客单)→ `charge-summary`(广告花费扫一眼)→ 退款组扫雷(异常才 `refund-item-list`)。落点:今天要不要处理什么。

**② 周复盘(深检)**
触发:"这周复盘"。动线:GMV 因子拆解(近 7 天趋势)→ 流量·场归因(`grow-factor` + 万相台 ROI,**用区间**)→ 转化漏斗(加购/收藏)→ 售后深挖(`refund-item-list` 按款 + 差评)→ 货·复购(`item-list` + 老客字段)。落点:下周调整方向。

**③ 测款专项**:`new-product-*`/`item-list` + 主图点击率/详情转化 + 万相台测款投放 → 这款能不能上量。

**④ 退货归因专项(女装刚需)**:退款率飙了 → `refund-item-list` 按款 + `evaluation-list` 差评 + 退款原因(尺码/面料)→ 揪问题款,改详情/尺码表/下架。

**⑤ 广告 ROI 复盘专项**:万相台 `report-keyword`/`report-campaign`/`scene-daily`(**用区间**) × sycm `grow-factor` 交叉 → 砍低 ROI 词/加高 ROI 预算。

**⑥ 客服质检专项**:`reception-list` + `evaluation-list`(差评) + `fetch-recent`(询单流失/慢响应常空,不主用)→ 接待质量、话术。

每套跑完收敛成 **"今天/本周该干的 1–2 件事"**。

## 6. 融合报表(跨 CLI)+ 互推

- **全店日体检**:sycm 大盘+退款 × 万相台广告 ROI → 一张"赚没赚/花值不值/有没有雷"。
- **单款 360**:sycm `item-list`+`refund-item-list`+差评 × 万相台 `promo-items` → 卖/退/投全景 → 补货/下架/停投。
- **广告×自然对照**:sycm `grow-factor`(广告引导成交) × 万相台 `scene-daily`(花费/ROI)→ 交叉验证真实广告效率。
- **互推**:sycm=数据体检 / alimama=广告投放 / qianniu=店铺查询,三件套,各自 README/SKILL 加"配套工具"区互相引导下载。

## 7. SKILL vs README 分工(硬规矩:分开)

| | SKILL(机器) | README(人) |
|---|---|---|
| 体检流程 | 6 套动线:命令序列 + "if X then Y" 判断 | 一段话讲思路 + "AI 照 SKILL.md 自动跑" |
| 报表体系 | 5 域清单 + 字段码 + 用途,供 AI 选报表 | 一张报表体系表 + 一个标准报表成品示例 |
