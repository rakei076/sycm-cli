# 单品诊断报告：AI 分析指南

单品诊断报告是生意参谋工具生成的七页网页报告。本指南说明如何取数、写分析和生成网页。当用户说「帮我诊断一下这个商品」「这个款为什么卖不动了」「做个单品分析报告 / 增长方案」时，按本指南操作。

报告是一个单文件网页，断网也能打开，可以直接发给他人。七页依次为：诊断总览、趋势图表、同店对标、下滑归因（支付金额没有下降时称为问题归因）、45 天方案、目标模拟器、数据缺口。数字、图表、表格和模拟器由程序根据数据生成，你负责撰写诊断和方案中的文字。

## 一、生成步骤

生成报告分为三步，其中取数约需两三分钟。

1. **取数**：运行 `scripts/sycm.sh item-report --item-id <商品ID>`。Windows 使用 `scripts\sycm.cmd`；已接入 MCP 时，用 run 工具运行，command 填写 `item-report`。
   - **商品范围**：商品必须属于当前登录的店铺。只知道货号或标题时，用 `--search 关键词` 代替 `--item-id`。
   - **`--days`**：只能取 7、15、30，生意参谋的单品数据只支持这几种窗口。报告分析前后两段连起来的整段时间：默认值 7 表示最近 14 天，用前 7 天和后 7 天对比；查看月度变化时用 30。
   - **`--end`**：最后一天，默认为昨天。
   - **`--compete 竞品对比.json`**：有达摩盘工具时，先运行 `scripts/dmp.sh compete-item --item <同一个商品ID> --out 竞品对比.json` 取得竞品对比文件，再用此参数带入。网页上没有竞品页，但数据文件中会包含达摩盘对本品的诊断、同类目中做起来的成功商品和打爆路径，以及与竞品的逐项对比，供你写归因和方案时作为证据。
   - **数据文件**：运行结束后会打印数据文件的位置：`reports/item-<商品ID>-<日期>-<天数>d.data.json`。
2. **写分析**：读取数据文件，按下文的方法写分析，存为同一目录下的 `item-<商品ID>-<日期>-<天数>d.analysis.json`。

   **提示**：该目录无法写入时（例如在沙箱中），请存到你可以写入的位置，并在第 3 步加上 `--data <数据文件>`。
3. **生成网页**：运行 `scripts/sycm.sh item-report --analysis <分析文件>`。分析文件有问题时，这一步会逐条列出需要修改的地方，修改后重新运行。看到「报告已生成」和网页路径，即表示报告生成完成。

   **提示**：如需发给他人（代运营、合作方、群聊），加 `--mask` 生成强脱敏版：隐去商品和店铺身份，金额、访客、买家、件数折算为指数，比率和趋势保留。

## 二、数据文件里有什么

| 键 | 内容 |
|---|---|
| `facts` | **先看这里**：程序算好的数。`核心对比`（前后两段，含搜索引导访客、占比、转化率）、`支付金额拆解`、`整段`（网页「结论摘要」的数）、`首末对比`（第一天和最后一天，网页同名表格）、`推广花费占支付金额`、`店铺`、`同店位置`（同店最佳、本品排名）、`基线`、`异常提醒`、`去年同期`、`深挖要点` |
| `meta` | 商品 ID、标题、类目（`cateName` 叶子类目、`topName` 一级类目）、两段的起止日期；`fields` 是英文键对应的中文名 |
| `halves` | 前后两段的单品汇总。访客、买家在段内去重，两段对比以它为准 |
| `daily` | 每天的明细，两段连在一起；`seUv`、`seByr` 是当天的搜索引导访客和买家 |
| `flow` | 两段的流量来源，每个渠道一行，`path` 如「经营优势/搜索」「付费推广/无界/关键词推广」 |
| `bench` | 后一段的全店商品排行，最多 60 个，含本品；`top` 是一级类目，`cateName` 是叶子类目名（和本品同一级类目的才有） |
| `shop_daily` | 店铺每天的访客、支付金额 |
| `deep` | 商品 360 各页签：`alarm` 问题预警（缺货、高价限流、质量问题）；`title` 标题里每个词引来的搜索访客和平台推荐词；`detail` 详情页本品 / 同行均值 / 同行优秀，以及逐屏的曝光、加购、跳失；`video` 主图视频；`sku` 各规格的加购和成交；`bundle` 关联搭配；`refund` 最近 30 天的退款原因和各 SKU 退款；`service` 服务体验；`content` 关联的短视频；`price` 挂牌价、价格带、类目；`profile` 访客画像 |
| `last_year` | 去年同期的单品汇总，商品去年没在卖就没有 |
| `compete` | 达摩盘，带了 `--compete` 才有：`单品洞察`（平台标签、生命周期、和同行同层比的指标、成长诊断原话、成功商品、打爆路径）和竞品逐项对比（竞品只给区间） |
| `errors` | 这次没取到的部分 |

`deep`、`flow`、`compete` 网页上不单独成页，是写两条硬伤、归因证据和动作的依据。

新版生意参谋的渠道这样看：免费搜索在「经营优势/搜索」，免费推荐在「经营优势/推荐」；「付费推广」下面是关键词推广、人群推广、全站推广等；「主动回访」是收藏、购物车、我的淘宝等；「店内流转」是从店里其他商品、店铺页过来的访客。

## 三、怎么诊断（按这个顺序看）

0. **先排雷**：
   - `deep.alarm`：本品在缺货名单里，或者店里有高价限流、质量问题商品 → 先说这个，其他都排在后面（缺货和限流直接卡流量）。
   - `facts.异常提醒` 里列出的日子，有人一次买或加购了很多件（批发、测试单或拍错）。含这些天的件数不能直接比，分析里要点明，别把它当成趋势。加购率按人数算，不受这种单影响。
1. **先定性**：看 `facts.支付金额拆解`。支付金额 = 访客数 × 支付转化率 × 客单价，哪个因子变得最多，问题主要就在哪：
   - 访客掉、转化不掉 →「量」的问题，是拿流量的问题；
   - 访客不掉、转化掉 →「率」的问题，是承接的问题：主图、详情、价格、评价、SKU；
   - 客单价掉 →「价」的问题：降价了、低价 SKU 卖得多、连带少了；
   - 几样一起掉 → 都写，按影响大小排。

   支付金额在涨也照样诊断：涨的原因能不能持续，还剩哪块短板。
2. **量：流量从哪来、哪个渠道掉了**（`flow`、`核心对比` 里的搜索引导访客）：
   - 比较两段各渠道的访客，掉得最多的一两个渠道就是线索。
   - 搜索引导访客占比低或在掉 → 搜索拿不到量。查标题关键词、类目属性、销量和评价权重。搜索进来的人转化率通常最高，搜索流失会把整体转化拉低。
   - 付费访客占比超过一半 → 流量靠买，停投就掉。再看推广花费占支付金额（这个比例不是 ROI）。
3. **率：承接**：加购率、支付转化率、详情页跳失率、平均停留。
   - 跳失率高、停留短 → 主图和详情前几屏没接住。
   - 加购率低 → 没打动人。
   - 加购了不买 → 看价格、优惠、评价、发货。
4. **同店对标**：看 `facts.同店位置`。同店对标比的是和本品同一个一级类目的商品（会混着几个叶子类目），「同店最佳」是其中访客够多、转化率最高的那个。本品和它的转化率、加购率差多少？同店卖得好的商品是最直接的模仿对象，学它的主图、SKU、详情、价格带。访客太少的商品转化率不稳，不拿来当标杆。
5. **人**：新客、老客各自怎么变。新客掉得比老客多 → 拉新出了问题，靠老客托底；全是新客、没有老客 → 没有复购和沉淀。
6. **大盘**：看 `facts.店铺`。店铺整体也在掉 → 有大盘或季节的因素。店铺稳、只有本品在掉 → 是本品自己的问题，本品是下滑的放大器。有 `last_year` 时看同比：去年这时候也在掉，多半是季节。
7. **细看承接和搜索**（`deep`）：
   - 标题（`deep.title`）：零引导的词白占标题字数，换成平台推荐词里热度高、竞争不太高的词。
   - 详情页（`deep.detail`）：加购转化率、跳失率、停留和同行均值、同行优秀比，差在哪项；逐屏找掉得最狠的一屏，动作写到具体哪一屏。这里的分母是详情页曝光人数，不要和总览的转化率混着比。
   - SKU：成交集中在一两个规格 → 主推它；很多规格没卖出去 → 精简或改成组合装。
   - 退款原因里「内部原因」才是自己能改的。
   - 主图视频：曝光点击率低 → 封面不吸引人；完播率低 → 前几秒没抓住人。
   - 访客画像：消费层级、性别年龄和目标客群对不上 → 引来的人不对，查主图、关键词和投放人群。
8. **达摩盘**（有 `compete` 才有）：平台标签、成长诊断、变化归因原话引用，作为佐证；「可参照的成功商品」看价格带和节奏；「打爆路径」是这类爆款常走的推广路线，方案的推广打法从里面挑。竞品数据一律写区间。

**样本小的时候**（比如一周只有几单），一两单就能让转化率跳很多。要明说「样本小，结论只能参考」，判断多依靠访客结构、加购、跳失这些人数多的指标。首末对比只有两天，波动更大，只当佐证。

## 四、45 天方案怎么定

方案叫「量·率·速」：量 = 访客和搜索引导访客，率 = 转化率、加购率、跳失率，速 = 客单价和日均支付金额。

- **基线**是 `facts.基线`：后一段的日均访客、日均搜索引导访客、日均支付金额，以及转化率、客单价、加购率、跳失率。
- **分阶段**：一般分 3 段，「止血修复（先修率）→ 流量放量（拿流量）→ 效率冲刺（提效率、接大促）」。每段天数可以调整，合计默认 45 天；要别的长度时改 `plan.days`。
- **先修率再放量**：转化率没修好就加预算，只会更快地花钱。
- **每个阶段写 `targets`**（这个阶段最后一天要达到的水平，程序会从基线一天天线性爬上去，画成每日门槛）：
  - 必填：`uv`（日均访客，相对基线的倍数，1.2 = 多 20%）、`cv`（支付转化率，写小数，0.025 = 2.5%）、`aov`（客单价，相对基线的倍数）。
  - 建议都写：`se`（日均搜索引导访客，倍数）、`cartRate`（加购率，小数）、`bounce`（跳失率，小数）。写了的，目标表和阶段卡片上才有这一行。
- **目标要有依据**：转化率目标不超过同店最佳；先回到前一段的水平是合理的第一步；45 天后日均支付金额一般比基线高 20%～80%，更高时在 `baseline_note` 里写清理由。有达摩盘成长诊断时，它说的「日均再成交多少有望到达爆品期」可以当最终目标的参照。
- **动作清单**写 10～15 条，每条讲清四件事：做什么、谁做（运营 / 设计 / 推广 / 客服 / 内容）、看什么指标、什么时候完成（D3、D7……）。动作要具体到能直接派工：写「主图重构：对标同店商品 100000000002 的首图结构，卖点前置（规格 / 材质 / 适用场景），A/B 测 3 组」，不写「优化主图」。
- **风险**写 3～5 条，每条配一个对策。

## 六、有对应工具时，再补几样

这几样不进报告的图表，但能让归因更扎实，查到了就写进 evidence 和 gaps：

- **差评原文**（千牛工具）：`scripts/qianniu.sh review-list --product-id <商品ID> --days 30`，追评再加 `--feed-type append`。看差评、追评集中在什么（尺码、质量、色差……），写进归因的证据。
- **竞品的买家在意什么**（竞品评价工具，用买家账号）：抓竞品的评价和问大家，看对方买家夸什么、骂什么，用来定本品的卖点和详情页。
- **万相台投放**（万相台工具）：各推广计划的花费、ROI、点击率、加购率。生意参谋里没有，投放有问题时查了写进证据和动作。

## 七、每周复盘

方案开始以后，每周跑一次：`scripts/sycm.sh item-report --track --analysis <分析文件>`。程序会从 D1 起逐天拿实际的支付金额和转化率，和每日门槛比，打印摘要（达标几天、最近 7 天日均和门槛差多少、连续几天没达标），再出一份填好实际数的跟踪表。

复盘这样写：
- 先说结论：这周在不在轨上（最近 7 天日均和门槛差多少）。
- 没达标就对照动作清单，看是哪条动作没做、没生效，还是外部原因（大促、断货、换季）。
- 下周怎么调：一般只调动作、不改目标；连续两周比门槛低 30% 以上，再考虑下调后面阶段的目标，并写清理由。

## 八、写法

照上面示例的口气写，像运营负责人写给老板的诊断：
- **先结论后证据。** 定性一句话能单独拿出来讲，用「不是……，而是……」把误判先排除掉。
- 硬伤标题带上是「量」「率」还是「速」的问题；每条要点都有数，关键数字用 `**加粗**`，变化写成「-41%」「+6.3pp」「17.9% → 10.1%」。
- 读图说明以「读图：」开头，说图里看到什么、说明什么。
- 归因按影响权重排，证据写数，动作写到能派工。
- **分析文字里不写绝对的金额、访客数、买家数、件数**，写变化、比率和排名。具体数字表格和图里都有；这样生成脱敏版时，文字也不会泄露店铺规模。
- **不写商品标题和店铺名。** 提到同店别的商品写它的 ID（「同店商品 100000000002」），脱敏时程序会换成代号。零引导的词里有品牌名时，写「品牌词」。
- 平台给的数写成事实；原因写「推断」或「可能」。从现有数据验证不了的，写进 `gaps`。
- 竞品数据写区间，不编精确数。样本小的时候明说。
- 除了 `**加粗**`，别的 Markdown 不要用。
